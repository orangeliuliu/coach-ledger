# 教練月收入對帳

健身教練的收入來自很多單位（健身房、公司福利課、私人學生）。這個網頁用來記錄每堂課有沒有開，月底再和各單位實際匯進來的金額對帳。

- 網址：https://orangeliuliu.github.io/coach-ledger/
- 使用者：教練一人，用一支手機（也可以在電腦上打開）
- 資料：存在手機瀏覽器裡，每次修改都會自動同步到教練的 Google 雲端硬碟

---

## 一、怎麼使用（給教練）

### 第一次設定（約 3 分鐘）

1. **加到主畫面**
   - iPhone：用 Safari 打開網址 →「分享」→「加入主畫面」→「加入」
   - Android：用 Chrome 打開網址 → 右上「⋮」→「加到主畫面」
2. **之後一律從主畫面的圖示打開。** Safari 分頁和主畫面 App 的資料是分開的兩份。從主畫面打開，Safari 也不會自動清掉資料。
3. **連線 Google 雲端硬碟**：按右上角「連線 Google 雲端硬碟」→ 選教練的 Google 帳號 → 出現「Google 尚未驗證這個應用程式」時按「繼續」→ 勾選允許存取雲端硬碟 →「繼續」。
4. 左上角出現綠點「已同步到雲端硬碟」就完成了。雲端硬碟裡會出現資料夾 `教練收入對帳`，裡面的 `教練收入對帳-自動同步.json` **不要改名、不要刪除、也不要移出資料夾**。同一個資料夾還會放每個月的自動備份（見「每月自動備份」）。

### 平常：只記例外

**每堂課預設都算「有開」**，不用每天打勾，只要處理「跟課表不一樣」的課。在「逐日記錄」分頁找到那一天：

| 操作 | 說明 |
|---|---|
| 按「停課」 | 這堂沒上，不計入（金額會劃掉） |
| 再按一次「停課」或按「有開」 | 恢復成有開 |
| 點金額數字修改 | 這一堂的薪水跟平常不同時使用，例如多了學生或代課費不同 |
| 「＋ 加一堂臨時課 / 代課」 | 課表以外的課，加入後直接算「有開」。可以從下拉選單帶入現有課程再修改，也可以每一格自己填 |

「逐日記錄」最上面是**本月月曆**，一眼看出每天的狀況：
- 每一格是一天，一個圓點代表一堂課：綠色是有開，紅色是停課，藍色是臨時加課，空心圓是還沒到的課。
- 有停課的日子，右上角會標「停 N」；手機上改成整格淡紅色。
- 電腦上每格下方會顯示當天有開的金額。
- 點任何一天，會直接跳到那一天的課程清單，並閃一下提示位置。

最上方的四格摘要會即時更新：

- **本月應收（已扣停課）**：這個月全部有開的課的金額合計
- **停課 · 沒收入**：這個月停了幾堂、少收多少
- **到今天為止已上**：從月初到今天（含）有開的課的金額
- **課表全開的話**：完全沒停課時，本月能收到多少

### 月底：對帳

到「對帳」分頁：

對帳頁有四個獨立的區塊（自營團課在自己的分頁，說明見下方）：

| 區塊 | 包含哪些課 | 怎麼對帳 |
|---|---|---|
| **團體課** | 課名不含「私教」或「私人課」的課，按**地點**合成一行 | 月底填「實收」 |
| **私教課 · 預繳** | 付款方式是「預繳」的學生，按**學生**合成一行 | 學生買課時「登記」，之後自動扣堂數 |
| **私教課 · 堂結** | 付款方式是「堂結」的學生（每上一堂當場收一堂） | 每堂收到錢就勾「已收」 |
| **私教課 · 月結** | 付款方式是「月結」的學生 | 月底填「實收」 |

對帳頁最上面有四個區塊的捷徑，各自顯示目前狀態（例如「還有 13 個未填」、「4 堂未收」），點下去會捲到那個區塊。

每位私教學生名字下面都有「付款」選單，可以在預繳、堂結、月結之間切換。沒有設定過的學生（包括臨時課的學生、「未寫名字」）預設是月結。切到預繳時，如果還沒有登記紀錄，會直接打開登記表單。

- 學生名字取自課名「-」後面的部分，例如「私教課 - 王小姐」、「私人課-陳」；沒寫名字的會列成「未寫名字」。
- 同一個地點的團體課會合成一行，所以地點名稱要寫得一致，例如都寫「XX 健身房 信義店」，不要有的寫「XX 健身房」。

### 自營團課（獨立分頁）

教練自己經營的團課（同一天、同一個地點的兩堂課，例如週日晚上的課程 A、課程 B）是**期課**。它們有自己的「**自營團課**」分頁，不列在「對帳」分頁裡。

**規則**
- 一期若干個日期（不一定 8 堂），兩堂課同一天上。只有這一期的日期會出現在逐日記錄，其他週的同一天不會有這兩堂課。
- 預繳比較便宜：分成**一種課程**、**兩種課程**兩種方案，另外有**單堂報名**價。每一期的價格可以不同。
- 學員可以**請假**，再選另一堂課**補課**；其他人可以**單堂報名**。
- 請假不退費、補課不另收費。

**分頁內容（由上到下）**
- **這一期設定**（最上面）：價格、單堂價、場地費和上課日期，說明收在「這些設定是做什麼的？」裡。
- **期數按鈕**：「第 1 期」「第 2 期」… 切換要看哪一期；預設顯示目前月份所在的那一期。舊的期數和它的點名、學費、單堂紀錄都完整保留。
- **＋ 開新一期**：填期名（自動帶下一期的期數）、第一堂日期（預設上一期最後一堂的下週）、幾堂、這一期的價格和場地費。日期會照每週排好，之後再到「這一期設定」刪掉放假的日子或加日期。
  - 勾「沿用上一期學員」會把名單帶過來：方案相同、學費照新價格、標成「**未繳費**」。收到錢時在學員表填繳費日，沒續報的按 × 刪掉。
  - 日期不能跟別期重疊。開錯了可以在「這一期設定」最下面「刪除這一期」（至少要留一期）。
- **總覽**：整期淨收入（學費 + 單堂 − 場地費）、本月收到的錢（繳費日在本月的學費 + 本月單堂）、本月上課金額（算進逐日記錄的那個數字）。
- **場次點名**：表格一列一個日期、一欄一堂課，每格顯示出席人數、請假/補課/單堂人數和這堂金額。點格子打開點名：
  - **期課學員**預設都有來，請假的人把勾勾拿掉（顯示「請假」）。
  - **補課**：從選單挑學員 →「＋ 補課」，不另收費。選單分兩組：
    - **這一期學員**：有請假還沒補的排在最前面，標「待補 N」。
    - **之前的期數，還沒補完**：上一期請假、到這一期才來補的人，標「第 N 期待補 1」。補完後，那一期學員表的「待補」會跟著減少。
  - **名單外的人補課**：不在任何名單上的人（其他館的學員、朋友等），在「名單外的人」填名字和備註（可不填）→「＋ 名單外補課」。算進出席人數、不收錢、不影響這堂金額。名字會記住，下次輸入時會提示。
    - **幫現有學員補（代補）**：名單外的人如果是代替某位學員來上課，在「幫誰補」選那位學員，再選「代替哪一堂的假」（已請假的日期排在最前面）。例如學員 A 11/8 要請假，朋友 B 10/4 幫他補：在 10/4 那堂填「朋友 B」、選「幫 學員 A 補」、選「11/8」。
    - 如果 11/8 還沒登記請假，會**一併登記**。學員表兩邊互相對照：請假「11/8（朋友 B 10/4 代補）」、補課「10/4（朋友 B 代 11/8）」。
    - 刪掉這筆代補時，連帶登記的請假也會一起取消；原本就登記的請假則保留。已經有人代補的那一堂，不會再出現在選單裡。
  - **單堂報名**：填名字、金額（預設是這一期的單堂價）→「＋ 單堂」。
  - 逐日記錄裡這兩堂課的「點名」按鈕打開的是同一個面板。
  - **停課**：點名面板右上角「這堂停課」，逐日記錄那堂也會變成停課；反過來在逐日記錄按停課，這裡也會顯示停課。停課的格子點一下就恢復。停課那堂不算錢、不扣場地費，學費改由其他有上的堂數分攤（整期學費不變，所以同一期其他堂的金額會跟著調整，包括前幾個月的）。
  - 臨時取消用「停課」；只有排錯的日期才到設定裡刪掉日期。
- **學員**：每位學員的方案（兩種課程 / 只上課程 A / 只上課程 B）、學費、繳費日、出席（到今天為止上了幾堂 / 方案總堂數）、請假和補課的日期，以及「待補 N 堂」提醒。
  - 換方案時，如果學費還是原本方案的定價，會自動換成新方案的定價；學費不同（例如打折）就不動。
  - **新增學員**：填名字、方案、學費（跟著方案帶入定價）、繳費日、從哪堂開始（期中加入的人選開始那天，學費只分攤到那天以後的課）。
  - **刪除學員**：按 ×（手機是「刪除」），確認後學費、請假、補課紀錄都刪掉，過去的課金額會重算。加錯人才用。
- **名單外補課**：這一期所有名單外補課，按名字分組，列出日期、課程和備註，按 × 刪除。
- **單堂報名**：整期所有單堂按人分組，同一人的多個日期列在一起；也可以在這裡直接選「哪一堂」新增，按 × 刪除。
- **這一期設定的內容**：這一期自己的一種 / 兩種課程價格（新增學員時帶入的學費，不動到已登記的人）、單堂價（單堂報名的預設金額）、場地費（每堂扣掉的金額），以及上課日期（只有這些日期會出現在逐日記錄；可加、可刪，改了之後每堂學費分攤會重算）。改這一期不影響其他期。

**每堂金額怎麼算**：這堂期課學員的學費分攤（學費 ÷ 有上的堂數）+ 單堂 − 場地費。例如 8 堂 $2,000 的方案每人每堂分攤 $250，10 位學員、場地費 $600 的那堂是 10 × 250 − 600 = $1,900。這個金額會算進逐日記錄和每月總額。

**團體課、私教課 · 月結：填實收**

1. 每一行列出本月有開幾堂、應收多少。
2. 錢入帳後，把實際收到的金額填進「實收」，旁邊會顯示：
   - 灰色「未填實收」：還沒對到這一行
   - 綠色「相符」
   - 紅色「少 X」：對方少給，要去問
   - 藍色「多 X」：對方多給
3. 每一區的右上角會顯示「還有 N 個未填」，全部填完才算對帳完成。差額只比較已填寫的那幾行。

**私教課 · 預繳：登記購買，自動扣堂數**

1. **第一次使用**：每位預繳學生按「登記」，二選一：
   - **購買課程（有收錢）**：例如「9/1 買 10 堂，收 NT$15,000」。金額會自動用「堂數 × 單堂價」帶入，可以再改。從購買那天起上的課會開始扣。
   - **目前剩餘堂數（不算收入）**：不記得什麼時候買的，就填「到今天還剩幾堂」。這天（含）以前的課視為已經扣完，從隔天起才扣。
2. **之後**：每上一堂（有開）自動扣 1 堂；按「停課」的不扣；臨時加的私教課也會扣。學生再買課時，同樣按「登記」→「購買課程」。
3. **看狀態**：

   | 標籤 | 意思 |
   |---|---|
   | 綠色「足夠」 | 剩餘堂數夠用 |
   | 黃色「快用完」 | 剩 2 堂以下，該提醒學生續約 |
   | 黃色「這個月會不夠 N 堂」 | 這個月還排的課比剩餘堂數多 |
   | 紅色「超上 N 堂，未付」 | 堂數已經用完還繼續上，要跟學生收 |
   | 灰色「還沒登記」 | 還沒輸入購買或剩餘堂數，不會扣 |

4. 手機上「登記 / 修正 / 明細」按鈕在學生名字下面，電腦上在每一行最右邊。按「明細」可以看每一次購買和上課扣堂的紀錄，學生問起時可以直接給他看。
   - **登記錯了**：學生那一行的「修正」按鈕會修正最近一筆登記；要改更早的，在明細裡那一筆旁邊按「修正」，表單會帶入原本填的類型、日期、堂數和金額，改完按「儲存修正」會直接取代那一筆，不會多出一筆。例如把「購買（有收錢）」改成「目前剩餘（沒收錢）」，本月收到的金額也會跟著更正。
   - 整筆不要了，按「×」刪除。
5. 區塊上方的「本月收到（購買）」是這個月學生買課付的錢，也就是實際入帳的現金。
6. 看過去的月份時，剩餘堂數算到那個月的月底；看這個月或之後的月份，算到今天。
7. 換成其他付款方式時，登記紀錄會保留，之後切回預繳還在。

**預繳的兩種扣法：按堂數 / 按時間**

每位預繳學生名字下面有「扣法」選單：

| 扣法 | 課程包單位 | 每上一堂扣多少 |
|---|---|---|
| 按堂數（預設） | 堂 | 固定扣 1 堂 |
| 按時間 | 小時 | 這堂實際上的分鐘數 ÷ 60 |

按時間的學生：
1. 在對帳頁那一行的「每小時 NT$」填每小時收費。沒填之前會用課表推算（例如 90 分鐘 3,000，等於每小時 2,000）。
2. 登記購買時填「買幾小時」，可以填 0.5 的倍數；金額會自動帶入「小時 × 每小時收費」。
3. 在「逐日記錄」，按時間學生的課會多一個「分」欄位，預設是課表的時長。上半堂就改成 30，會扣 0.5 小時，那堂的金額也自動變成「每小時收費 × 0.5」。
4. 剩餘、快用完（2 小時以下）、這個月會不夠、超上，都照小時計算。

**私教課 · 堂結：逐堂勾選已收**

1. 每位學生一行，列出到今天（看過去的月份則到月底）已上幾堂、應收、已收，以及「N 堂未收」或「都收齊了」。
2. 收錢的方式有兩種，效果一樣：
   - 在「逐日記錄」，堂結學生的課旁邊有「收款」按鈕，收到錢按一下就會變成「已收」。
   - 在對帳頁按「逐堂勾選」，勾選收到錢的那幾堂；也可以按「全部標為已收」。
3. 還沒上的課不算應收；按「停課」的課也不算。

另外，最上方摘要的第一格改叫「本月上課總額（已扣停課）」，指的是這個月有開的課依單堂價的總和，包含預繳學生的課。預繳學生實際收到的錢要看「本月收到（購買）」。

用左上角的「‹ ›」切換月份。資料從 **2026 年 9 月**開始記。

### 課表有變動

到「每週課表」分頁，可以新增、修改或刪除固定課。

- 新增、修改或刪除，**只影響今天以後的課**。今天以前的課會保留當時的時間、地點和金額，過去的帳不會變。
- 把課改到另一個星期幾時，舊的那堂會停在昨天，從今天起改成新的星期。
- 如果以前某一天的課跟課表不同，不要改課表，請到「逐日記錄」的那一天改金額、按停課或加臨時課。
- 課名用「私教課 - 名字」的格式，對帳時就會按學生分開列。

### 看懂左上角的狀態

| 顯示 | 意思 | 要做什麼 |
|---|---|---|
| 🟢 已同步到雲端硬碟 · 時間 | 手機和雲端都有最新資料 | 不用做什麼 |
| 🟡 同步到雲端硬碟中… / 準備同步… | 正在上傳 | 等幾秒 |
| 🟡 有變更還沒存到雲端硬碟 · 請按「重新連線」 | Google 登入過期（每小時一次） | 按右上角「重新連線雲端硬碟」 |
| 🟡 沒有網路 | 目前沒有網路 | 有網路後會自動補傳 |
| 🔴 紅字說明原因 | 同步失敗 | 看紅字的說明，或按「重試同步」 |

不論顯示哪一種狀態，資料都已經存在手機裡，不會不見。

### 電腦和手機都在用

同步是雙向的：
- **打開頁面、切回這個 App 時**，會先檢查雲端硬碟上有沒有其他裝置更新的資料，有的話自動載入，並提示「已載入其他裝置的最新資料」。
- **上傳前也會檢查**：雲端上的資料如果被其他裝置改過，就不會直接覆蓋。
- **兩邊都有改**（例如手機斷網時改了，同時電腦也改了），畫面上方會出現黃色提示條，選一份：
  - 「用雲端硬碟的」：這台的修改會被捨棄。
  - 「用這台的（覆蓋雲端）」：其他裝置的修改會被蓋掉。
- Google 登入過期時，左上角會顯示「請按『重新連線』取得其他裝置的最新資料」，按右上角的按鈕，或點一下畫面任何按鈕都會自動續約。

建議同一時間只在一台裝置上記錄，比較不會遇到要二選一的情況。

**立即同步（手動）**：右上角「⟳ 立即同步」按鈕（連線雲端硬碟後才會出現）。想確定剛填的資料已經上傳時按它，會依序：
1. 先載入其他裝置的新資料；兩邊都有改就請你選一份。
2. 把這台的資料完整上傳一次。
3. 從雲端讀回來逐項比對，一致才顯示「已確認：這台的資料都在雲端硬碟 · 時間」。

沒有網路、登入過期或比對不一致時，會直接告訴你原因；登入過期時按下去會自動重新登入再同步。

### 換手機或資料被清掉

在新手機照「第一次設定」再做一遍。連線後，頁面發現手機裡沒有記錄，會自動把雲端硬碟上的資料載回來。

### 備份選項（右上角選單）

- **從雲端硬碟載回資料**：用雲端硬碟上的資料蓋掉這支手機的資料
- **匯出備份檔**：另外存一份 `.json` 檔，手機上會跳出分享選單
- **從備份檔還原**：選一個匯出的備份檔還原
- **打開雲端資料夾（每月備份）**：在新分頁打開雲端硬碟的 `教練收入對帳` 資料夾
- **中斷雲端硬碟連線**：停止自動同步，雲端上的檔案會保留

### 每月自動備份

- 每個月第一次打開網頁、同步完成時（通常就是 1 號），會在 `教練收入對帳` 資料夾存一份備份，檔名是當天日期，例如 `2026-10-01.json`。如果 1 號沒打開，就在那個月第一次打開的那天備份，檔名是那天的日期（例如 `2026-10-03.json`）。
- 每個月只會有一份：電腦和手機都在用時，先打開的那台備份，另一台看到資料夾裡已經有了就不會再存。
- 網頁沒有打開就不會備份（它是網頁，不是一直在背景跑的程式），也需要是已連線雲端硬碟的狀態。有衝突提示條或還沒同步完時會等同步好再備份。
- 備份檔跟「匯出備份檔」格式一樣，要還原時：從雲端硬碟下載 → 備份選項 →「從備份檔還原」。
- 開始使用這個功能的當月不備份，從下個月 1 號開始。

### 注意事項

- 可以電腦和手機一起用，但同一時間在兩台都改，會需要二選一（見「電腦和手機都在用」）。
- 不要用無痕模式打開，關掉就會消失。
- 雲端硬碟會自動保留同步檔的舊版本，改錯了可以在雲端硬碟裡對檔案按「管理版本」找回來。

## 二、怎麼實作（給維護的人）

### 架構

```
index.html（單一檔案，沒有後端）
 ├─ 畫面：原生 HTML / CSS / JavaScript，不依賴任何框架
 ├─ 儲存：瀏覽器 localStorage（主要資料）
 └─ 同步：Google Identity Services + Google Drive API v3
          → 教練雲端硬碟裡的一個 JSON 檔
```

- 放在 GitHub Pages 的靜態網站上，沒有伺服器和資料庫，不花錢。
- 字型從 Google Fonts 載入。沒網路時會改用系統字型，功能不受影響。

### 資料結構

所有資料放在 localStorage，key 的前綴是 `coach-ledger:`。

| Key | 內容 |
|---|---|
| `config/schedule` | 每週固定課表 `{classes:[...], v:版本}` |
| `config/selfrun` | 自營團課 `{v:4, cids:['c30','c31'], terms:[{id, name, dates:[上課日期], price:{one:一種課程, both:兩種課程}, single:單堂價, venue:場地費, students:[{id, name, pkg:'both' 或課程編號, fee:學費, paid:繳費日（空白＝未繳費）, from:從哪天開始}]}]}`。價格放在每一期裡，開新一期不會改到舊的。舊版（v1/v2 每堂一份名單、v3 價格放在最外層）載入時自動轉成 v4 |
| `config/prepaid` | 私教學生的付款方式與預繳登記 `{v:3, students:{名字:{mode:'prepaid'或'perclass'或'monthly', unit:'class'或'time', rate:每小時收費, entries:[登記紀錄]}}}`（舊資料用 `on:true` 代表預繳，仍然相容） |
| `months/2026-10` | 某個月的記錄（每月一筆） |
| `meta/drive` | 雲端同步狀態（檔案 id、上次同步時間、是否有未同步變更） |
| `meta/token` | Google 存取權杖（1 小時有效） |
| `meta/backup` | 上次備份時間 |

`meta/*` 只記在本機，不會被備份或同步。

**課表中的一堂課：**
```json
{"id":"c02","dow":1,"time":"10:45","dur":60,"place":"某某地點","content":"私教課 - 王小姐","pay":1500}
```
`dow` 代表星期：0 = 日，1 = 一 … 6 = 六。可以另外帶 `from` / `until`（`YYYY-MM-DD`），代表這堂課從哪天開始、到哪天結束。

**改課表時怎麼保護過去的帳：**
- 修改時間、地點、金額等欄位：先用 `freezePast()` 把 `START_MONTH` 到昨天、這堂課每一天的舊資料寫進 `snap`，再套用修改。
- 刪除：不真的刪，而是設 `until = 昨天`，所以過去的日子還是有這堂課。今天才新增的課則直接刪掉。
- 改星期：舊的那堂設 `until = 昨天`，另外複製一堂新的，設 `from = 今天`。
- 新增：`from = 今天`。

**一個月的記錄：**
```json
{
  "entries": {
    "2026-10-05_c02": {"s":"held", "pay":1800, "snap":{...當時的課程資料...}}
  },
  "extras":   [{"id":"x...","date":"2026-10-07","time":"12:00","place":"...","content":"...","pay":900,"s":"held"}],
  "received": {"private｜某某地點｜王小姐": 6000, "group｜XX 健身房": 12000}
}
```
- `entries` 的 key 是「日期_課程id」。**沒有記錄的課預設是有開**；`s:"off"` 代表停課（舊資料裡可能有 `s:"held"`，意思一樣是有開）。只有被動過的課才會有這一筆。
- `pay` 只在金額和課表不同時才會存。
- `snap` 保存當時的課程資料。某一天有 `snap` 時，就用 `snap` 顯示，不看目前的課表。
- `extras` 是臨時課或代課。
- 按時間學生的某堂實際分鐘數存在 `entries` 的 `mins`（臨時課存在它自己的 `mins`）；沒有就用課表時長。
- `att` 是自營團課的點名：`{"2026-10-04_c30": {leave:[請假的學員 id], makeup:[來補課的學員 id，可以是之前期數的學員], guest:[{name, note, for, forKey, auto}]（名單外補課，不收費；`for` 是被代補的學員 id、`forKey` 是代替的那一堂，算成他的補課；`auto` 表示那堂的請假是這筆一併登記的）, single:[{name, amount}]}}`；沒有這筆代表期課學員全到、沒有補課和單堂。每堂的點名存在那堂課所在的月份。
- `paid` 是堂結學生已收款的課，`{"2026-09-02_c13": true}`，key 跟 `entries` 一樣是「日期_編號」（臨時課是它的 id）。
- `received` 是對帳時填的實收金額，key 是對帳的那一行（見下方）。沒有這一筆，就代表還沒填（未對帳）。
- 舊資料裡可能有 `kind`（類型）欄位，現在已經不用，畫面上也不顯示。

**預繳的登記紀錄：**`{"id":"p...","type":"buy","date":"2026-09-01","count":10,"amount":15000}` 是購買；`type:"set"`（沒有 amount）是「到這天為止剩 count 堂」。剩餘堂數由 `ledgerOf()` 依日期排序計算：同一天先算購買、再扣當天的課、最後套用「目前剩餘」；最早一筆登記以前的課不扣。上過的課由 `heldPrivateClasses()` 從 `START_MONTH` 起逐月找出。

**對帳怎麼分行：**課名含「私教」或「私人課」的課是私教課，key 是 `private｜地點｜學生`（學生取自課名「-」後面，沒寫名字就用「未寫名字」）；其他是團體課，key 是 `group｜地點`。見程式裡的 `sources()`、`isPrivate()` 和 `clientOf()`。

**每個月的課怎麼產生：**`daysOfMonth()` 會用課表把那個月每一天展開，再合併 `entries`、`extras`，以及課表已刪除但有記錄的舊課。

### Google 雲端硬碟同步

- 登入：Google Identity Services 的 Token Client（`initTokenClient`），權限範圍是 `drive.file`。
  - `drive.file` 只能存取這個 App 自己建立的檔案，看不到雲端硬碟裡的其他東西。
  - 存取權杖 1 小時到期，沒有 refresh token，因為純前端拿不到。
  - 到期後，使用者下一次點「有開 / 停課」時，會自動用 `prompt:''` 靜默續約（5 分鐘內最多一次）。失敗的話，會顯示「重新連線」按鈕。
- 資料夾：`ensureFolder()` 找或建立 `教練收入對帳` 資料夾（`application/vnd.google-apps.folder`），id 記在 `meta/drive.folderId`。同步檔建立時放在資料夾裡；舊版放在雲端硬碟最上層的同步檔，`moveIntoFolder()` 會用 `PATCH files/{id}?addParents=…&removeParents=…` 移進去一次（`meta/drive.inFolder`），移動後更新 `known`，不會被當成別台的修改。
- 每月備份：`monthlyBackup()` 在 `syncCheck()` / `pushNow()` 成功、沒有衝突也沒有未上傳修改時執行。`meta/monthly` 記 `from`（開始使用的月份，當月不備份）和 `done`（這台已處理的月份）；上傳前查資料夾裡有沒有 `YYYY-MM-` 開頭的檔案，沒有才用 multipart `POST` 建立 `YYYY-MM-DD.json`。
- 上傳：每次修改後等 1.5 秒，把整份資料用 `PATCH upload/drive/v3/files/{id}` 覆寫到同一個檔案。第一次上傳時用 multipart `POST` 建立檔案。頁面切到背景時會立刻上傳。
- 雙向同步：`meta/drive.known` 記住這台最後一次同步時雲端檔案的 `modifiedTime`。
  - `syncCheck()` 在打開頁面、切回 App、視窗取得焦點（15 秒內最多一次）、重新登入後執行：雲端的 `modifiedTime` 跟 `known` 不同時讀回內容；內容相同只更新 `known`；這台沒有未同步的修改就自動載入（`pullRemote()`）；兩邊都改了就顯示衝突提示條。
  - `pushNow()` 上傳前也做同樣的檢查，雲端被別台改過就不覆蓋，改為顯示衝突提示條；選「用這台的」才會強制上傳（`forcePush`）。
  - 比對內容用 `stable()`（物件 key 排序後的 JSON）。
  - `manualSync()`（立即同步按鈕）：`syncCheck()` → 強制上傳 → `readRemote()` 讀回來用 `stable()` 比對。
- 新裝置保護：上傳前，如果本機沒有任何月份記錄、雲端卻有，會改成**載入雲端資料**，不會用空資料蓋掉雲端。
- 錯誤處理：
  - 401 或權限不足：清掉權杖，請使用者重新連線
  - Drive API 未啟用：顯示明確的紅字說明
  - 429 或 5xx：20 秒後自動重試
  - 其他錯誤：60 秒後自動重試
  - 斷網：網路恢復時自動補傳

### 可以調整的設定

檔案開頭的設定區：
```js
const GOOGLE_CLIENT_ID = '....apps.googleusercontent.com'; // Google Cloud 的 OAuth 用戶端 ID；留空就關閉雲端同步
```

主程式裡：

| 常數 | 用途 |
|---|---|
| `START_MONTH` | 最早能看的月份，目前是 `'2026-09'` |
| `DRIVE_FILE` / `DRIVE_FOLDER` | 雲端硬碟上的同步檔名和資料夾名。改了會變成新建一個檔案 |

**網頁本身不含任何資料**：`index.html` 只是框架，課表、學生名字、地點、價格、自營團課的期數和學員全部存在資料裡（瀏覽器 localStorage、雲端硬碟的同步檔、備份 .json）。所以 `index.html` 可以放在公開的 GitHub repo。第一次打開是空的，會提示「連線 Google 雲端硬碟」或「從備份檔還原」。

課表的每堂課有固定編號（c01～c31，新課用 `'c'+時間` 產生的編號），記錄用「日期_編號」存。**已經用過的編號不要改**。舊版（課表 v6 以前、自營團課 v3 以前）的自動轉換已經移除，因為現在的資料都已是新格式。

### 部署

**1. GitHub Pages**（2026-09-30 起，取代 Netlify；Netlify 免費方案每月只能部署約 20 次）

1. repo：公開的 `coach-ledger`，放 `index.html`（網頁框架，不含資料）和這份 README。**不要把備份 .json、自動同步 .json 放進 repo**，裡面有學生和收入資料。
2. 設定：repo → Settings → Pages → Source 選「Deploy from a branch」→ Branch 選 `main`、資料夾 `/ (root)` → Save。
3. 更新：repo 首頁 →「Add file」→「Upload files」→ 拖入新的 `index.html` →「Commit changes」。一兩分鐘後生效（可在 repo 的「Actions」看進度）。
4. 網址：`https://orangeliuliu.github.io/coach-ledger/`。網址不要再換：瀏覽器的資料跟著網址（網域）存，換網址後要重新「連線 Google 雲端硬碟」把資料載回。

**2. Google Cloud**

1. 到 https://console.cloud.google.com ，確認最上方選的是這個網頁用的專案。
2. **啟用 API**：「API 和服務」→「程式庫」→ 搜尋 Google Drive API →「啟用」。
   直接連結：https://console.cloud.google.com/apis/library/drive.googleapis.com
3. **OAuth 同意畫面**：「Google Auth Platform」→ 應用程式名稱、支援 email → 目標對象選「外部」。
4. **測試使用者**：「目標對象」→「測試使用者」→ 新增教練的 Google 帳號。
   直接連結：https://console.cloud.google.com/auth/audience
   沒有加入的話，登入會出現「已封鎖存取權 … 403 access_denied」。
5. **用戶端 ID**：「憑證」→「建立憑證」→「OAuth 用戶端 ID」→ 類型選「網頁應用程式」→ 在「已授權的 JavaScript 來源」填 `https://orangeliuliu.github.io`（只填網域，不含 `/coach-ledger`，結尾不加斜線），重新導向 URI 留空。
6. 把用戶端 ID 填進 `index.html` 的 `GOOGLE_CLIENT_ID`，再重新部署。只需要用戶端 ID，**用戶端密鑰（GOCSPX- 開頭）不用，也不要放進檔案**。

應用程式維持在「測試」狀態就可以用，登入時會出現一次「Google 尚未驗證」的提示，按「繼續」即可。

### 疑難排解

| 狀況 | 原因 | 解法 |
|---|---|---|
| 登入顯示「已封鎖存取權 / 403 access_denied」 | 帳號不在測試使用者名單 | Google Cloud →「目標對象」→ 新增測試使用者 |
| 紅字「這個 Google Cloud 專案還沒啟用 Google Drive API」 | Drive API 沒啟用 | 到程式庫啟用，等一分鐘再按「重試同步」 |
| 登入視窗顯示 `origin_mismatch` 或 `redirect_uri_mismatch` | 已授權的 JavaScript 來源和網址不符 | 檢查網址完全一致，前面是 https、結尾沒有斜線 |
| 右上角沒有「連線 Google 雲端硬碟」按鈕 | `GOOGLE_CLIENT_ID` 是空的，或瀏覽器還在用舊版 | 確認有填 ID 並重新部署，再重新整理頁面 |
| 資料不見了 | 瀏覽器資料被清除、用了無痕模式或換了網址 | 連線雲端硬碟會自動載回；或從選單「從雲端硬碟載回資料」 |
| iPhone 主畫面 App 的 Google 登入視窗卡住 | iOS 主畫面 App 的彈出視窗限制 | 關掉 App 重開再試。仍然不行的話，改用 Safari 分頁操作並把分頁留著 |

### 已知限制

- 多台裝置同時修改時不會自動合併，而是讓使用者選一份。
- Google 存取權杖每小時到期，續約要使用者點一下畫面。
- iPhone 主畫面 App 的 Google 登入沒有經過實機完整測試。
